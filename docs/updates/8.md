# SDK adapters, Python SDK, and dial-in-only agent hosts

PR: [#8](https://github.com/trytilde/tilde/pull/8)

## Intent of the change

Agents could only be written comfortably with the Vercel AI SDK in TypeScript, and Tilde
still had code paths that called agents: signed `Invoke`/`Healthz` requests to an agent
endpoint, a sidecar HTTP wake fallback, and sidecar replicas posting work to each other.

After this change:

- LangChain/LangGraph, OpenAI Agents and Mastra have TypeScript adapters with the same
  message and tool conversion as the Vercel adapter, each with an example agent.
- A Python SDK exists (`sdk/py`, uv workspace): the `trytilde` core plus LangChain,
  Pydantic AI, OpenAI Agents, Agno and CrewAI adapters, a FastAPI helper and the chat proxy, each
  adapter with an example agent.
- Tilde never calls an agent and replicas never call each other. A host dials in with its
  deployment token and receives wakes as `RunService.Watch` frames. Every internal
  connection is agent to gateway, agent to its local sidecar, or sidecar to gateway.
- `REGISTER_DEV_AGENTS=1 task dev` registers and starts one example agent per adapter.

## Architecture changes

ADR review: [ADR 0004](../adrs/0004-agent-webhook-signing-key.md) (caller-supplied webhook
signing key) is superseded by this change: agents have no endpoint and no signing key, so
there is nothing to sign. No replacement ADR is added here; the decision is recorded in
`CONTEXT.md` ("Agent host", "Agent deployments and sidecars").

```mermaid
flowchart LR
  Agent["Agent host (connectAgent / connect_agent)"] -- "Watch, Heartbeat, Report, callbacks" --> Gateway
  SidecarAgent["Agent beside a sidecar"] -- "same protocol on loopback" --> Sidecar
  Sidecar -- "Watch, Publish, Hydrate, Forward" --> Gateway
  Provider["Provider webhook"] --> Sidecar
  Sidecar -- "Forward(provider event) when another replica holds the thread" --> Gateway
  Gateway -- "directive on the holder's own Watch stream" -.-> Holder["Holder replica"]
```

## Summarized changes

- **Contracts:** `tilde.agent_host.v1` keeps only the `InvokeRequest` wake message. Agents
  lose `endpoint_url` and `webhook_signing_key`; `WatchRequest` loses `public_url`; the
  sidecar lease loses `holder_public_url`; `ForwardRequest` gains `provider_event`.
- **Engine (`crates/tilde`):** removed the signed HTTP agent client, the sidecar wake
  fallback and Healthz probe worker, `ENGINE_SIDECAR_AGENT_ENDPOINTS`, signing-key sealing,
  agent endpoint validation, and the sidecar peer client, route, token and hand-off. A
  sidecar wake requires a connected local agent process. Provider events for a conversation
  held elsewhere go through the gateway, which waits for the holder's result so failures
  reach the webhook caller. Agent creation no longer creates a deployment.
- **Schema:** migration `20260917010000_agent_dial_in_only.sql` drops
  `agents.endpoint_url` and `agents.webhook_signing_key`, deletes historical HTTP probe
  rows, and renames `agent_health.endpoint_url` to `instance_id`.
- **TypeScript SDK:** removed `createAgentServer`, `createAgentHandler` and signature
  verification. `connectAgent` defaults from `TILDE_GATEWAY_URL`/`TILDE_DEPLOYMENT_TOKEN`
  and takes a `ready` hook sent with every heartbeat. New packages
  `sdk-langchain-node`, `sdk-openai-agents-node`, `sdk-mastra-node`.
- **Python SDK:** `connect_agent`, `run_connected_agent`, `create_lambda_handler`,
  FastAPI `agent_lifespan` and `mount_chat_proxy`, management/runtime/Tilde chat clients,
  per-invocation OTLP traces and logs, and the four adapters.
- **Examples:** TypeScript example agents moved to `sdk/ts/examples/` (`vercel-ai-`,
  `langchain-`, `openai-agents-`, `mastra-`, `basic-example-agent` and `langsmith-agent`).
  CrewAI is Python only; it cannot share an environment with the OpenAI Agents SDK (openai
  major version conflict), so it is locked as a uv conflict and synced into `.venv-crewai`.
- **Web, scripts, CI:** the agent form has no signing key; the sidecar snippet uses
  `connectAgent`; CI installs uv; Python packages share the Changie release version.
- **Validation run:** TypeScript unit tests and the `chat`, `concurrency` and
  `attachments` integration suites; Python unit tests and the real-engine integration test;
  all Rust test targets under the dial-in model; a live check that all nine example agents
  dial in with open watch streams and ready heartbeats.
- **Unverified:** the example agents have not been run against a live model (no OpenAI key
  was available). `web/scripts/test-client.mjs` was updated but needs a full embedded-web
  build to run. One sidecar projection test flakes about one run in six, identically on main.
- **Request compression:** the engine accepts gzip request bodies (`connectrpc` `gzip`
  feature). The chat provider ingress paths, which read the body to authorize and route it
  before the Connect handler and may forward it to another replica, decompress unary and
  enveloped streaming bodies once at the edge. Python clients use their default gzip request
  compression; the Python integration test exercises it end to end.

## Critical to apply

yes

- **Breaking for every agent host.** Hosts must switch to `connectAgent` / `connect_agent`
  with a deployment token. Inbound agent endpoints, `AGENT_SIGNING_KEY`, and
  `ENGINE_SIDECAR_AGENT_ENDPOINTS` no longer exist.
- **Register deployments explicitly.** Creating an agent no longer creates a deployment; an
  agent without a registered, connected deployment cannot serve.
- **Migration is destructive.** It drops the agent endpoint and signing-key columns and
  deletes historical HTTP health probe rows. Deploy the gateway, sidecars and SDK hosts
  together; older sidecars and hosts do not interoperate with the new contracts.
- **API consumers:** `CreateAgent`/`UpdateAgent` no longer accept `endpointUrl` or
  `webhookSigningKey`, and `Agent` no longer returns `endpointUrl`.
