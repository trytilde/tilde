## v3.1.1 - 2026-10-03
### Added
* quickstart/compose.yaml runs the latest Tilde image with PostgreSQL, ClickHouse and MinIO on your machine: create an encryption key in quickstart/.env, run docker compose up -d and open http://127.0.0.1:8080.
* The `tilde` CLI: `tilde dev` matches this project's name against an agent you registered (it never creates one), registers a deployment carrying the prompts, skills and tools the code declares, runs the agent with the credentials it needs and serves a local chat page to talk to it, re-registering and restarting when a declaration changes; `tilde deploy` is the same registration for CI and `tilde doctor` checks the project, its SDK and the gateway. Install it with `curl -fsSL https://trytilde.ai/install.sh | sh`, from npm as @trytilde/cli or from PyPI as trytilde-cli; both SDKs ask for the matching version, so `npx tilde` and `uv run tilde` keep the CLI and the SDK on one version.
### Changed


* The SDKs now only read what an agent declares, and the CLI registers it: `@trytilde/sdk` exposes `tilde-declarations` instead of `tilde`, and the Python SDK `tilde-declarations` (or `python -m tilde declarations`) instead of `python -m tilde deploy`. Both print the DeploymentDeclarations JSON that `tilde deploy` uploads and registers, so registration has one implementation rather than one per SDK. Set `command: npx tilde deploy dist/index.js --json` in the register-deployment action as before.
* Generated Rust contracts moved from `crates/tilde/src/generated` into their own `tilde-contracts` crate, so the engine and the `tilde` CLI build against one set of Protobuf messages and ConnectRPC clients instead of the CLI restating the wire shapes by hand. The engine re-exports them as `crate::proto` and `crate::services`, so its own paths are unchanged; `task generate` now writes into the new crate.
* The quickstart now runs with no setup at all: `docker compose up -d --wait` generates the encryption key on first start, keeps it in a Docker volume and reuses it on restart, so there is no .env to create (set TILDE_ENCRYPTION_KEY to supply your own). It also health-checks the gateway against /readyz, so `up --wait` returns only once it can serve instead of racing the next command, and quickstart/.env is gitignored in case you make one.

## v3.1.0 - 2026-10-01
### Changed

* Rust builds go through sccache and tests run with cargo nextest, locally and in CI, and CI caches compiled crates, the Cargo registry, code generators, pnpm and uv. The telemetry queue's admission lock is scoped to the database schema, so installations sharing a database no longer wait on each other's queues.

## v3.0.1 - 2026-09-30
### Changed

* First published release of open-source Tilde: the container image on GHCR and the SDKs on npm and PyPI. It contains everything in 3.0.0, which was prepared but never published.

## v3.0.0 - 2026-09-30
### Added
* Support agent sidecars that cache conversations in memory beside the agent process and execute the threads they hold a lease on, taking the lease in the same gateway call that hydrates a thread and paying no per-event gateway calls afterwards; they dial the gateway over one connection for configuration, leases, projection and forwarding, and relay traces and logs through the gateway. The gateway serves every route group on one listener selected by ENGINE_SERVE.
* Collect agent OTel logs through Rotel into ClickHouse, independently forward to external collectors, and browse correlated logs in the agent Logs tab.
* Register agent deployments from CI or the UI with per-deployment tokens, route new threads to the serving deployment and pin existing ones, and record each invocation's deployment so instances, failover and history stay scoped to it.
* Wake-and-dial run protocol. Long-running hosts dial the gateway with their deployment token and receive wakes as frames, Lambda deployments are woken through the AWS invoke API, and every host reports acceptance, reasoning and completion through RunService with its invocation capability; the SDK gains connectAgent and createLambdaHandler.
* Sidecar agents dial their sidecar over the run protocol with the deployment token, so the HTTP endpoint map and health probe become optional fallbacks; sidecars leave gracefully by releasing idle leases and reporting themselves gone, and keep cached conversations within a per-agent byte budget.
* Preserve agent queue, interrupt and batch policies across gateway and sidecar runtimes; add provider sending identities, typed SDK history and channel tools, the Vercel AI SDK adapter, and automatic local example-agent startup.
* Inference gateway that forwards agents' provider SDK traffic (OpenAI, Anthropic, Azure OpenAI, Azure AI, Google AI Studio, Bedrock, Baseten, Cerebras, Vercel AI Gateway, Cohere, Voyage) by connection slug with the invocation token, swaps credentials from memory on gateway and sidecar, accounts usage off the request path, and warms channel tools, credentials and first-page history when an invocation starts.
* Inference cost tracking priced from a vendored LiteLLM price sheet at insert time, agent and identity budgets (day, month or total; block or flag) settled by a worker and enforced through the invocation token's inference claim on gateway and sidecar, and a management InferenceService for usage and budgets.
* Add framework adapters for LangChain/LangGraph, OpenAI Agents and Mastra to the TypeScript SDK with example agents, and a Python SDK workspace (`trytilde` core with the ConnectRPC agent host, FastAPI mounting and chat proxy, plus `trytilde-langchain`, `trytilde-pydantic-ai`, `trytilde-openai-agents`, `trytilde-agno` and `trytilde-crewai` adapters with example agents). `REGISTER_DEV_AGENTS=1 task dev` now registers and starts one example agent per adapter, filtered by `DEV_AGENTS`.
* Accept gzip-compressed Connect request bodies on every listener, including the chat provider ingress and sidecar relay paths that read the body before the Connect handler; the Python SDK no longer disables request compression.
* Tilde stores agent traces, logs and metrics itself. Agents upload OTLP to /v1/traces, /v1/logs and /v1/metrics on the gateway or their sidecar. Batches are queued in object storage (ENGINE_TRACES_S3_BUCKET, ENGINE_LOGS_S3_BUCKET, ENGINE_METRICS_S3_BUCKET) with a pointer in Postgres, so gateways are stateless and any replica delivers what another accepted; each queue bucket needs a lifecycle rule of at least a day. Batches are stored in ClickHouse (ENGINE_CLICKHOUSE_*, retention set by ENGINE_CLICKHOUSE_RETENTION_DAYS, unset keeps everything) and can also be forwarded to any OTLP/HTTP collector (TRACES_OTLP_*, LOGS_OTLP_*, METRICS_OTLP_*). The Tracing, Sessions and Logs tabs read them through the management API under a mandatory agent scope, with search by name, type, level, model, session, invocation, input and output text, numeric comparisons and any span attribute. Generation spans are priced from the inference price table. Base64 media and payloads over 64 KiB move to ENGINE_MEDIA_S3_BUCKET and are rendered in the inspector.
* Prompt management and agent skills. `tilde deploy` (TypeScript and Python SDKs) registers a deployment together with the prompts and skills its code declares, read from the agent framework's own objects (Mastra, Vercel AI SDK and eve, LangChain, OpenAI Agents, CrewAI, Pydantic AI, Agno) or from definePrompt/defineSkills; prompt versions are content-hashed in plain, mustache, braces or dynamic form, the inference gateway links every call to the versions that produced it so cost, tokens and latency compare per version, and the Prompts and Deployments tabs show history, diffs, usage and what each deployment shipped. Bundled skills are pinned per deployment and private to their agent; registry skills reach every deployment live through each framework's own skill mechanism. Skills are grouped into skill sources (Tilde catalog groups, GitHub repositories synced hourly and on request, or editor collections) with a Skills page; files live content-addressed in ENGINE_SKILLS_S3_BUCKET. Agents are given whole sources, single skills, or the skills linked to a connection through its new skills capability, and read them through ctx.skills; the skills.edit capability lets an agent author into and sync the sources it targets. The agents.edit_skills capability unlocks runtime skill management on the targeted agents.
* Agents use tools Tilde manages. On an agent's Tools tab you add a tool connection or a tool server, pick which of its tools the agent uses and which run in the background, and choose whether they are listed or found by search; agents see them as `source.tool`. Tools come from managed providers (Google Workspace, GitHub, Slack, Sentry, PostHog, Firecrawl, Stripe, Payload, Tavily, Linq, AgentMail, WhatsApp, E2B, Modal, AWS), 23 curated MCP servers, MCP servers added by URL (with dynamic OAuth client registration), and customer tool servers that dial in or run on Lambda, optionally with credentialed instances. The Tools area lists connections, a browsable catalog and remote servers.
* Agents declare bundled tools, shipped in their code and run in their process, the way their framework already defines tools, and hand them to the adapter's `withTildeTools` (TypeScript) or `with_tilde_tools` (Python), which returns the framework's own tools. Their descriptions, summaries, schemas and hints are published on every invocation, so tool search describes them beside Tilde's tools and the agent's Tools tab lists them read-only, and each call is recorded with its summary. The Python SDK gains tool summaries, annotations, output schemas and `ctx.tool_source`. Traces show the tool `tools.execute` ran beneath it and cover a background tool's work until it finishes.
* Agents have a description, shown and edited inline under the agent's name. The agents home page has a filter bar: search matches names and descriptions, and agents can be filtered by health (healthy, degraded, unhealthy, unknown) and by whether they are paused. Filtering happens on the server, so every page of results is filtered.
* `tilde deploy` declares an agent's bundled tools with the deployment: native framework tools in a `defineTools` / `define_tools` value exported from the entry, and the static tools of recognised framework agents, described exactly as `withTildeTools` / `with_tilde_tools` publishes them. `GetDeploymentContents` returns them and `--dry-run` prints them.
### Changed
* Version the Rust binary and TypeScript SDK packages together using Changie.

* Deliver steering, cancellation and suspension through execution-owned control subscriptions. Support Node serverless handlers and remove inbound host control RPCs and synchronous pause acknowledgements.
* Generated TypeScript contracts move into the @trytilde/contracts package, built from the protos on demand and no longer committed; the web app and SDK import from it instead of carrying duplicate copies.
* Sidecar publishes project lease releases in queue order, the projection checks thread membership on every event, Lambda deployments can serve gateway agents, routing enforces the pinned deployment, hosts report failed runs, hydration restores goals, tasks, conversions and run origins, a draining or fenced sidecar stops its agent process through the command stream, and the liveness window is one constant.
* Move native chat to the Tilde ConnectRPC provider with encrypted API keys, identity-scoped access, session search/read state and queue controls; add embeddable React chat, a server proxy and Next.js routes.
* The built-in Tilde chat provider is now a catalog provider like the others: every agent owns one system-managed Tilde connection, created with the agent, whose application key is the connection's credential. Its access mode and asserted identities live where every other provider keeps them, so the agent's access tab lists it beside the connections with public, private or disabled modes (private by default) and per-identity allow switches, with no provider-specific handling; identities asserted by the application are recorded on first contact and can be added ahead of time. The access tab also refreshes when it is opened so providers added moments earlier appear without a reload. Agent settings tabs moved to a row under the breadcrumb, and provider setup failures are logged with the provider's reason.
* Releases run automatically when a release PR's version lands on main. They publish the container image to GHCR (`ghcr.io/trytilde/tilde`), every public `@trytilde/*` npm package and the Python SDK packages to PyPI through trusted publishing, and attach the packages to the GitHub release; native binary archives are no longer published. Release preparation bumps the Python SDK lockfile with its manifests and accepts an explicit version. Encryption contexts and the container user are named `tilde`.
### Removed
* Remove every gateway-to-agent and sidecar-to-agent HTTP call. Agent hosts only dial in (`connectAgent` / `connect_agent`) and receive wakes as `RunService.Watch` frames; the `AgentService` Invoke/Healthz contract, `createAgentServer`/`createAgentHandler`, wake signatures, agent endpoint URLs, webhook signing keys, the sidecar HTTP fallback (`ENGINE_SIDECAR_AGENT_ENDPOINTS`) and HTTP health probes are gone. Sidecar replicas no longer call each other: work for a conversation held elsewhere goes through the gateway. Agent creation no longer creates a deployment; readiness comes from heartbeats.
