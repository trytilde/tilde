# Example agent (CrewAI)

Run with `REGISTER_DEV_AGENTS=1 task dev`. The debug-only `tilde dev-agent` command registers
**Example Agent CrewAI (Python)** (`4a1d7c90-8e53-4b2f-9c16-d0e7f3a5b609`) with its own Gateway
deployment and starts it from `sdk/py/.venv-crewai`; it dials in, so it listens on no port.
Set `DEV_AGENTS=py-crewai` to start only this one.

A local development agent mirroring the other SDK examples, built on CrewAI and the Tilde
Python SDK. Set `TILDE_GATEWAY_URL` and `TILDE_DEPLOYMENT_TOKEN` (the token comes
from registering a Gateway deployment for the agent), then run `python main.py` from this
directory (`OPENAI_MODEL` defaults to `gpt-5.6-terra`). The host dials out to Tilde and exposes
no endpoint.

The model receives only `ctx.channel.current` tools and responds by calling them. Returned
model text remains private; visible responses are provider tool actions. Attachments are
downloaded through the scoped SDK and converted into content parts or text by
`trytilde-crewai`.

`main.py` configures the dial-in Tilde host (`run_connected_agent`) and sets
`CREWAI_DISABLE_TELEMETRY=true` before importing CrewAI. `agent.py` follows the CrewAI project
layout: the `ExampleCrew` `@CrewBase` class builds its `responder` from `config/agents.yaml`
(`tasks.yaml` is empty; the responder runs no tasks), with a module-level `LLM` and the
`skills/` folder (`tilde.define_skills`). Per invocation it instantiates the crew with the
channel's tools and the skills assigned to the agent in Tilde (`ctx.skills.directory()`, so a
newly assigned skill needs no redeploy) and calls `Agent.kickoff_async` with the converted history, capped at eight
iterations (`max_iter`). History, attachments and reply routing are owned by the SDK through
`ctx.message.history()`, `convert_to_crewai_messages` and
`convert_to_crewai_tools(ctx.channel.current)`. CrewAI does not expose the model's tool-call
id, so audited tool calls carry ids generated by the core. Logs go through the standard
`logging` module, which the core routes to Tilde.

Model calls go through Tilde's inference gateway with `tilde.inference(TILDE_INFERENCE)` (default
`default`, the alias the local registrar gives the example's OpenAI connection), so the process
never holds a provider key; the LLM is built once and each request carries the running
invocation's token.

The YAML prompts and the skill are registered with the deployment, not at runtime. Preview them
from this directory with `../../.venv-crewai/bin/python -m tilde deploy main.py --dry-run`;
`tilde dev` does the same when it registers the example.
