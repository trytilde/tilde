## v3.0.0 - 2026-09-28
### Added
* Support agent sidecars that cache conversations in memory beside the agent process and execute the threads they hold a lease on, taking the lease in the same gateway call that hydrates a thread and paying no per-event gateway calls afterwards; they dial the gateway over one connection for configuration, leases, projection and forwarding, and relay traces and logs through the gateway. The gateway serves every route group on one listener selected by ENGINE_SERVE.
* Integrate Langfuse with durable trace forwarding, an agent-scoped native viewer, sidecar relay support, and automatic local development setup using Compose defaults with .env overrides.
* Collect agent OTel logs through Rotel into ClickHouse, independently forward to external collectors, and browse correlated logs in the agent Logs tab.
* Register agent deployments from CI or the UI with per-deployment tokens, route new threads to the serving deployment and pin existing ones, and record each invocation's deployment so instances, failover and history stay scoped to it.
* Wake-and-dial run protocol. Long-running hosts dial the gateway with their deployment token and receive wakes as frames, Lambda deployments are woken through the AWS invoke API, and every host reports acceptance, reasoning and completion through RunService with its invocation capability; the SDK gains connectAgent and createLambdaHandler.
* Sidecar agents dial their sidecar over the run protocol with the deployment token, so the HTTP endpoint map and health probe become optional fallbacks; sidecars leave gracefully by releasing idle leases and reporting themselves gone, and keep cached conversations within a per-agent byte budget.
* Preserve agent queue, interrupt and batch policies across gateway and sidecar runtimes; add provider sending identities, typed SDK history and channel tools, the Vercel AI SDK adapter, and automatic local example-agent and Langfuse startup.
* Inference gateway that forwards agents' provider SDK traffic (OpenAI, Anthropic, Azure OpenAI, Azure AI, Google AI Studio, Bedrock, Baseten, Cerebras, Vercel AI Gateway, Cohere, Voyage) by connection slug with the invocation token, swaps credentials from memory on gateway and sidecar, accounts usage off the request path, and warms channel tools, credentials and first-page history when an invocation starts.
* Inference cost tracking priced from a vendored LiteLLM price sheet at insert time, agent and identity budgets (day, month or total; block or flag) settled by a worker and enforced through the invocation token's inference claim on gateway and sidecar, and a management InferenceService for usage and budgets.
* Add framework adapters for LangChain/LangGraph, OpenAI Agents and Mastra to the TypeScript SDK with example agents, and a Python SDK workspace (`trytilde` core with the ConnectRPC agent host, FastAPI mounting and chat proxy, plus `trytilde-langchain`, `trytilde-pydantic-ai`, `trytilde-openai-agents`, `trytilde-agno` and `trytilde-crewai` adapters with example agents). `REGISTER_DEV_AGENTS=1 task dev` now registers and starts one example agent per adapter, filtered by `DEV_AGENTS`.
* Accept gzip-compressed Connect request bodies on every listener, including the chat provider ingress and sidecar relay paths that read the body before the Connect handler; the Python SDK no longer disables request compression.
* Authorize management access with roles. A role is a named set of actions on agents; every agent is created with three system roles, reader (view), editor (view, edit, share) and deployer (view, deploy, share), and users, groups and API keys hold any number of them. Sharing stays within reach: assigning a role needs share on the agent and every action the role gives, so editors hand out reader and editor, deployers reader and deployer, and administrators anything. Agents are shared from a people icon in their header, which searches users and groups, offers each role with what it allows, and can open the agent to every signed-in user. Installation-wide reader, editor and deployer roles over every agent, including ones created later, are assigned by administrators, to people or to API keys at creation. The API key page chooses reader or editor on all or selected agents and whether the key manages deployments. The sidebar groups API keys and groups under IAM. Without a role an agent is not found. Deployments, channel access, budgets, sessions, logs and traces follow their agent; connections and identities carry no roles. Groups are administrators, all users, external groups mirrored from the OIDC group claim at login, and locally managed groups. Any signed-in user may create agents and is their editor and deployer. API keys no longer have full authority, join no groups and never manage access; agent capability edits are bounded by the editor's own access; every management RPC applies its own rule and a test covers all of them. This governs the control plane only: the agent runtime listener, including trace, log and metric upload, still takes only the agent's invocation token and capabilities. Existing users remain administrators, existing keys hold nothing until given a role, and the first user of a new installation becomes an administrator. Configure ENGINE_OIDC_GROUPS_CLAIM, ENGINE_OIDC_SCOPES, ENGINE_OIDC_ADMIN_GROUPS and ENGINE_OIDC_ADMIN_SUBJECTS.
### Changed
* Version the Rust binary and TypeScript SDK packages together using Changie.

* Deliver steering, cancellation and suspension through execution-owned control subscriptions. Support Node serverless handlers and remove inbound host control RPCs and synchronous pause acknowledgements.
* Generated TypeScript contracts move into the @trytilde/contracts package, built from the protos on demand and no longer committed; the web app and SDK import from it instead of carrying duplicate copies.
* Sidecar publishes project lease releases in queue order, the projection checks thread membership on every event, Lambda deployments can serve gateway agents, routing enforces the pinned deployment, hosts report failed runs, hydration restores goals, tasks, conversions and run origins, a draining or fenced sidecar stops its agent process through the command stream, and the liveness window is one constant.
* Move native chat to the Tilde ConnectRPC provider with encrypted API keys, identity-scoped access, session search/read state and queue controls; add embeddable React chat, a server proxy and Next.js routes.
* The built-in Tilde chat provider is now a catalog provider like the others: every agent owns one system-managed Tilde connection, created with the agent, whose application key is the connection's credential. Its access mode and asserted identities live where every other provider keeps them, so the IAM tab lists it beside the connections with public, private or disabled modes (private by default) and per-identity allow switches, with no provider-specific handling; identities asserted by the application are recorded on first contact and can be added ahead of time. The IAM tab also refreshes when it is opened so providers added moments earlier appear without a reload. Agent settings tabs moved to a row under the breadcrumb, sharing is an icon button beside it, and provider setup failures are logged with the provider's reason.
* Releases publish every public `@trytilde/*` SDK package to npm and the open-source image to `ghcr.io/trytilde/tilde` (tagged `<version>`, `<major>.<minor>` and `latest`), and run automatically when a release PR's version lands on main. Release preparation bumps the Python SDK lockfile with its manifests, and accepts an explicit version. Encryption contexts and the container user are named `tilde`.
### Removed
* Remove every gateway-to-agent and sidecar-to-agent HTTP call. Agent hosts only dial in (`connectAgent` / `connect_agent`) and receive wakes as `RunService.Watch` frames; the `AgentService` Invoke/Healthz contract, `createAgentServer`/`createAgentHandler`, wake signatures, agent endpoint URLs, webhook signing keys, the sidecar HTTP fallback (`ENGINE_SIDECAR_AGENT_ENDPOINTS`) and HTTP health probes are gone. Sidecar replicas no longer call each other: work for a conversation held elsewhere goes through the gateway. Agent creation no longer creates a deployment; readiness comes from heartbeats.
