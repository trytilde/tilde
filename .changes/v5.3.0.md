## v5.3.0 - 2026-11-22
### Added
* `@trytilde/iac`: agent configuration in code (`defineAgent`, `defineProject`, `connection.ref`, `blueprint`, `egress`, `routine`, `lambda`/`gateway`/`sidecar`), with typed catalog providers (`github.ref("acme").tools("github_get_issue")`) whose tool names are string-literal unions generated from the built-in catalog, `ALL` (`"*"`) and `.untypedTools()` for anything else. `tilde deploy` applies the specs an entry exports in one `ApplyService.Apply` call, prints the plan or every required action with its link, supports `--dry-run`, `--json` and `--team`, and exits 2 when blocked; entries without specs register their deployment as before.
* `@trytilde/iac`: `secret.ref("NAME")` references a secret set in Tilde (Connections → Secrets) from a sandbox blueprint's environment; the value never enters the spec, and `tilde deploy` prints a link that adds a missing one.
* `@trytilde/iac`: people in code for Tilde Cloud: `defineTeam({ team, users, groups })`, `user()` and `group()` (declared with an object, referenced by email or name), users and groups beside an agent, and `access: [grant(group("eng"), "ownership")]`; users upsert their name, `login: true | { role }` sets the team role and invites, `team: { delete: true }` leaves the team, and `delete: true` disables a user or deletes a group. `tilde deploy` sends them with the agents, or alone for a team-only project.
* SDKs: `serve({ run })` (TypeScript) and `serve(run=...)` (Python) host an agent wherever its entry module runs: inside AWS Lambda it is the Lambda handler (`export const handler = serve({ run })`), with a deployment token it connects a dial-in host, and on a plain import (or while `tilde deploy` reads the module) it does nothing, replacing the Lambda-or-dial-in branch in entry modules.
* `tilde iac types` writes a `.d.ts` from the organization's own connections (MCP servers and tool hosts' instances): it augments `@trytilde/iac`'s new `Connections` interface, so `connection.ref("acme_mcp/prod")` takes that connection's type and tool names and a typo does not compile. Slugs it does not list, and `untypedTools`, still take plain strings.
* `tilde local`: connect a harness on your machine to a local agent, an agent Tilde lists and equips but never runs. `tilde local install claude-code|codex|claude-desktop --url <gateway> --agent-id <id>` stores the agent's key in `~/.tilde/local`, adds the harness's hooks and registers `tilde local mcp` as its MCP server, so the agent's tools reach the harness without the key entering its configuration. The hooks report each Claude Code and Codex session to Tilde as a thread (prompts, answers and finished tool calls, sent once and resumed from a cursor) and keep the agent's skills in the harness's own skill folder; `tilde local uninstall` removes all of it. Contracts: `Agent.local` (harness and the features its adapter supports), `CreateAgentRequest.harness` and `tilde.local.v1.LocalAgentService`.
* Chat and signal providers: Google Chat as a chat provider; Linear connections with tools and issue/comment signals; Sentry regression and alert signals; CloudWatch alarm signals through SNS on AWS connections; and filters on signal routines.
* AWS connections reach other accounts through assumed roles (assume_role_arns, external_id, an account_id argument on every AWS tool and aws_list_accounts), and a new oidc connection type federates with Tilde's own OpenID Connect issuer (ENGINE_TOKEN_ISSUER_URL, discovery and JWKS under /oidc) instead of access keys.
* Native chat: an application's user lists the providers an agent may use for them, connects their own account on Tilde's hosted setup page, and lists, reconnects or removes their connections (`ChatService` `ListConnectableProviders`, `StartConnection`, `ListConnections`, `ReconnectConnection`, `DeleteConnection`), for the agent's personal tools in their conversations. Owners choose which agents may use their personal connections (every agent granted `tools.personal` for the provider, the default, or only listed agents), enforced in the invocation catalog and on every call; personal tool calls record the connection they ran on.
* Sandbox egress on the server: blueprints grant sandboxes a connection's upstream through the gateway at `/sandboxes/egress/{slug}/…` with a minted credential that never enters the VM. Connection types gain the `egress` capability (GitHub App, personal access token and OAuth connections first); SetBlueprintEgress and DeleteBlueprintEgress manage a blueprint's grants, whose config only narrows the provider's rules; git fetch and push (granted branches only, never deletes, rewrites or the default branch) and a small REST allowlist are checked, and every request is traced on the sandbox's invocation. The blueprint page gets an Egress section.
* Declarative apply on the server: `ApplyService.Apply` makes the registry match agent specs written in code (agent, inference aliases, tool sources, sandbox blueprint with environment and egress, routines and the already-deployed deployment) in one transaction, upserting by key and removing only entries marked `delete`; preflight lists every required action first and a dry run returns the plan. Secrets (Connections → Secrets, `SecretService`) keep named, write-only values that a sandbox blueprint's environment can reference, read when a sandbox process connects.
* Local agents: an agent that runs in a harness on a person's machine (Claude Code, Codex, Claude Desktop, ChatGPT Desktop) is registered with `CreateAgent`'s `harness` (Agent Registry → Connect local agent). Tilde never runs it; its harness reports sessions through `tilde.local.v1.LocalAgentService` (one thread per session, every event a span) and reads the agent's skills, and `/agents/{agent}/mcp` serves the agent's tools as an MCP server.
* Tilde runs in a schema of its own beside another application's tables: with `options=-c search_path=<schema>,public` on `DATABASE_URL`, migrations create the schema when it is missing. `DATABASE_DIRECT_URL` optionally names the server behind a transaction-pooling PgBouncer `DATABASE_URL`, used only for migrations and the one LISTEN session per process.
* `@trytilde/iac`: `defineProject({ ontologies: { <name>: ontology({ environments: { <env>: { slots, secrets } } }) } })` declares a project's ontologies (Tilde Cloud, each in the repository's `ontologies/<name>/`) and each environment's connection slot and secret bindings; `ontology<typeof slots>()` types a slot's binding by its provider (`ConnectionRef` now carries `provider`). `tilde deploy` deploys them before the agents, changing nothing until everything is checked (the ontologies' preflight and the agents' dry-run Apply, every missing project, environment, connection and secret with a link): then a version per ontology from the repository at HEAD, checked against the spec, and each environment bound and rolled out in turn (`--only ontologies|agents`, `--ontology <name>`, `--allow-dirty`, `--accept-rebuild <model>`). A server without ontologies answers that they need Tilde Cloud.
### Changed

* Registry pages live under `/registry` (agents, skills, tools, sandboxes, memory and wikis); `/` opens the registry. The Connections page splits connections by what they are for (Tools & chat, Inference & embedding, Sandboxes, and Other) above the source tabs, and adds inference and sandbox connections from their tab. Memory facts and wiki pages are edited in a rich Markdown editor.
* Connections mint the credentials consumers send upstream through one service: a stored credential as it is, or GitHub App installation tokens and AWS STS sessions, cached until shortly before they expire. Health probes are no longer traced, unmatched routes are traced only on a 5xx, and ENGINE_CLICKHOUSE_CA_CERT pins a self-hosted ClickHouse's CA.
* Sidecar-hosted agents get their tool sources, not just channel tools. Agent heartbeats no longer queue behind other notifying commits on a busy Postgres. AWS SigV4 signing encodes the canonical path for every service but S3, so Lambda wakes are accepted. Web errors no longer start with the RPC code, and a missing agent links back to the registry.
