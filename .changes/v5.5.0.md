## v5.5.0 - 2026-11-23
### Added
* A project's root `tilde deploy` releases every agent that declares `deploy`, after its ontologies and their bindings. Each agent's code is in `agents/<key>/`, or wherever `defineAgent({ code })` names (an entry module, or a folder with its own package.json or pyproject.toml); `tilde deploy` reads each one's prompts, skills and tools there and registers a deployment with an external ID of its own. An agent with neither has its code in another repository: its spec is applied, it is not released, and a note says so. From an agent's own folder, the one deploying agent without code of its own releases the entry's declarations, so `tilde deploy` there works as before. A deploy with several deploying agents prints each new dial-in token as a `<key> <token>` line; with one, the token alone. `--check` no longer reads the agents' code.
* Declarative apply sets an agent's chat channels: an agent spec's `channels` assigns channel connections (Slack, Google Chat and the rest) and sets each channel's access mode, the agent's own Tilde chat included. Preflight lists a missing channel connection with a link, and refuses one another agent has. A channel the spec leaves out stays; `delete` unassigns one.
### Changed

* An existing `agents/<key>/` folder without its own package.json or pyproject.toml now fails `tilde deploy` with an error naming the folder, instead of being read as part of the project around it.
* `@trytilde/iac` connection refs accept names with spaces (`google_chat/Google Chat`), as the app lets people name connections; a name still cannot start or end with one.
* An agent folder may hold its own `tilde.config.ts`: the agent's release, like `tilde dev`, reads the package's code entry (`main`, `dist/index.js`, ...), never the config.
* `tilde deploy` from an agent's own folder releases that agent's code: when the folder is the agent's own (named after its key, or under `agents/`), its `tilde.config.ts` declares only that agent and its package's code entry exists, that package is its code. A config-only repo declaring one remote agent still applies its spec without a release. `tilde dev`'s fallback command runs the package's code, never its `tilde.config.ts`.
* Declarative apply of channels: tightening a channel's access stops the runs it no longer allows, a new channel starts in its provider's own mode (GitHub's is disabled) so a repeat changes nothing, an unsupported mode or two agents claiming one connection are required actions before anything is written, and deleting a channel another agent has is a no-op.
### Removed
* `tilde.toml` is gone. The CLI finds a project's `tilde.config.ts` at its root; agents' code comes from `agents/<key>/` or `defineAgent({ code })`; a project without a config keeps its package's conventions for its entry (`main`, then `dist/index.js`, then `src/index.ts`; Python's `src/agent.py` and so on), and `--entry` still overrides it. Ontology projects are named by their key in `defineProject({ ontologies })`, and `tilde dev` starts an agent with its package's `dev` or `start` script.
