## v5.6.0 - 2026-11-25
### Added
* Hosted deployments (Tilde Cloud): `deploy: { target: "hosted" }` in `@trytilde/iac`, or `tilde deploy --target hosted`, has Tilde run the agent's code itself. `tilde deploy` bundles the code with esbuild (`dist/index.mjs` exporting `handler`, with `prompts/` and `skills/`) and publishes it once the deployment is registered (`DeploymentService/PublishHostedDeployment`; an open-source server refuses it). A blueprint spec names its sandbox `connection` (it was `provider`) like any connection reference; on Tilde Cloud every team has the Tilde sandbox connection `tilde_sandbox/sandbox`, whose blueprints run `debian-node`, `debian-python` or `debian-full`.
* `@trytilde/chat-ui`: `Chat.fetch` replaces the cookie-carrying fetch for agent discovery and every ChatService call, so a host can send a bearer token instead (Tilde Cloud spaces' `<AgentChat>`) or answer from fixtures in tests and Storybook.
* `@trytilde/iac`: `lambda(functionArn, role)` names the IAM role Tilde assumes to invoke a Lambda deployment (`targetRole`). Tilde Cloud requires it and assumes it with the organization's ID as the external ID.
* One theme for every embedded UI: `@trytilde/chat-ui`'s `Chat`, `ListSessions` and `Transcript` take `theme` (the `Theme` that `@trytilde/embed` gives a space) and derive their palette from its tokens, with `scheme` choosing light or dark without a `.dark` ancestor; `@trytilde/embed`'s `mountConnectionSetup({ theme })` (plus `setTheme`) and `<ConnectionSetup theme>` style Tilde's setup page, including provider pages built on `useSetup`. The type now lives in `@trytilde/sdk/theme`; Tilde's own setup dialog follows the app's light or dark.
* `@trytilde/chat-ui`'s `Chat` (also `@trytilde/embed/react`'s) takes `header={false}` to show only the transcript and the message bar. The chat pane no longer draws a right border, and its hover washes (message actions, header actions, the attach button and its menu rows) come from the palette's `--hover`, which a theme derives from `ink`, instead of a fixed grey.
* Ten more built-in connection providers for the software factory, each with tools for agents: GitLab (access token on gitlab.com or a self-managed URL, or an OAuth app), Jira Cloud (API token or OAuth 2.0 3LO), Entire (service account secret and cluster host), Datadog, Grafana, Prometheus, PagerDuty (API key or OAuth), New Relic, Honeycomb and Terraform (HCP Terraform or Terraform Enterprise). GitLab and Entire are git forges with sandbox egress like GitHub: a blueprint's grant narrows to projects or repositories and push branches (default `factory/*`), sandboxes clone and push through the gateway (`entire://` remotes included, with no remote helper), and the credential never enters the VM. Atlassian, GitLab, Datadog, New Relic and Honeycomb's hosted MCP servers join the same providers as `mcp_oauth` types. `@trytilde/iac` has typed refs for all ten (`gitlab.ref(...).tools(...)`).
* `tilde deploy` (Tilde Cloud ontologies): a first deploy creates the ontology's project (in the deploy's team) and each environment the organization does not have yet, instead of asking for them to be created by hand; the plan lists what it creates. `@trytilde/iac`: an ontology environment takes `live` (`environments: { production: { live: true } }`), set when the deploy creates the environment.
### Changed

* Ontology slots are connections: `defineProject({ ontologies: { <name>: ontology({ environments: { <env>: { connections, secrets } } }) } })` replaces `slots`, `ontology<typeof connections>()` types the bindings by the ontology's own `connections`, and `tilde deploy`'s plan says `connection <name>`.
* `tilde deploy` prints deployment tokens only for dial-in hosts (gateway, sidecar): a Lambda or Hosted deployment's token is never printed.
* `tilde deploy` bundles a Hosted agent's linked prompt and skill files with their content, and refuses a linked folder (or names a broken link) in `prompts/` or `skills/` with a clear message.
* `tilde deploy` and `@trytilde/iac` send and read only `name`/`connections`: they need Tilde Cloud with the connections rename, and `slots` is no longer read.
* `@trytilde/chat-ui`: a refused proxy request shows its Connect error message instead of "Sign in to chat" or "Unable to load agents"; `ListSessions` takes `fetch` like `Chat` (both must be stable or memoised); a viewer who is not yet in the thread posts naming no participant, for the server to bind (Tilde Cloud spaces join the viewer on their first post).
* The sandbox egress route checks and forwards a request's path as the client sent it, still percent-encoded, instead of decoding it first: an encoded slash (`%2F`) in a GitHub REST path is now refused rather than read as a path separator. Escapes of unreserved characters are decoded before the rules are checked, so escaping a letter of a denied path (`%61ctions/secrets`) does not sidestep the rule, and a `%` that starts no escape is refused.
* `tilde deploy` (Tilde Cloud ontologies): a connection the ontology declares optional (`{ provider, optional: true }` in its `connections`) no longer has to be bound or in the spec; the deploy reports it as skipped and rolls out without it. `--check` on an ontology whose project does not exist yet is refused: Tilde compiles an ontology for its project, which the first deploy creates.
